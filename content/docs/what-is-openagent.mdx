# Architecture

OpenAgent is an open-source platform designed to bridge the gap between **raw Large Language Models (LLMs)** and **production-ready AI systems**. It provides the essential orchestration, data indexing, and tool-calling infrastructure needed to build reliable, knowledge-backed AI agents.

## The Core Philosophy

Unlike simple chat interfaces, OpenAgent is built on the principle of **Decoupled Intelligence**. We believe that an agent's identity, knowledge, and capabilities should be independent of the underlying LLM provider. This allows you to swap models (e.g., from GPT-4 to a local Llama 3) without rebuilding your entire knowledge base or tool-set.

## Architectural Layers

OpenAgent organizes AI complexity into four distinct functional layers:

### 1. Intelligence Layer (Providers)

Connect to any AI backend. OpenAgent abstracts the differences between providers, giving you a unified interface for:

- **Models**: Reasoning and chat (OpenAI, Anthropic, Ollama, DeepSeek, etc.)
- **Embeddings**: Turning text into searchable vectors
- **Tools**: Connecting to external APIs or MCP servers

### 2. Identity Layer (Stores)

The **Store** is the central unit of OpenAgent. It defines a specific agent's persona:

- **System Instructions**: The core "rules" of the agent
- **Memory Management**: How much conversation history to retain
- **Fallback Logic**: Automatic routing to secondary models if the primary fails

### 3. Context Layer (RAG)

Turn static documents into a living knowledge base:

- **Files**: Automatic parsing of PDF, Markdown, and Excel
- **Vectors**: Atomic, searchable chunks of your data
- **Retrieval**: Semantic search that finds the right info at query time

### 4. Action Layer (Tools)

Empower agents to do more than just talk:

- **Built-in Tools**: Web search, browser automation, and shell execution
- **A2A (Agent-to-Agent)**: Delegate tasks to specialized sub-agents
- **MCP**: Support for the industry-standard Model Context Protocol

## Request Lifecycle

When a user sends a message, OpenAgent performs a coordinated orchestration dance:

1. **Grounded Retrieval** — The query is embedded and matched against indexed Vectors.
2. **Context Assembly** — The system prompt, history, and retrieved document snippets are merged into a high-density context.
3. **Reasoning & Tool Call** — The LLM processes the request. If it needs external data, a Tool call is triggered and executed server-side.
4. **Final Delivery** — The result is streamed back to the user and recorded for auditing.

## Why OpenAgent?

| Advantage | Description |
|-----------|-------------|
| **Enterprise Ready** | Out-of-the-box support for SSO (Casdoor), auditing, and token usage tracking |
| **Vendor Neutral** | No lock-in. Run on-premise with local models or in the cloud |
| **Atomic Scaling** | Start with a single chat assistant and scale to a complex network of delegated agents |
